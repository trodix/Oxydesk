RustyDesktop

Your KDE Plasma desktop, from any RDP client

Open source · AGPL-3.0 · written in Rust

Download Install in two minutes

A Plasma session on Debian 13 served by rdsktp and displayed in FreeRDP.

A real session, not a screen mirror

Each user who connects gets a genuine logind/KDE session, started after a PAM login. Close the client, come back later: your windows are still there.

🔐

Native Linux login

PAM authentication over TLS with your existing accounts. One isolated session per user, with throttling per client address and per account.

🔁

Survives network drops

After a cut, mstsc and FreeRDP reconnect by themselves, without the password. The session and its applications are kept.

⚡

Modern video path

H.264 over the RDP graphics pipeline (EGFX), software OpenH264 or GPU VA-API, with bitrate adapted to the client's link.

Everything you expect from a remote desktop

Tested with Windows mstsc, FreeRDP (xfreerdp, sdl-freerdp) and Remmina.

🖥️

Multi-monitor and resize

Up to 16 monitors, dynamic resize through Display Control, layouts that follow the client.

📋

Clipboard

Text, images and files in both directions, including very large files streamed without being stored.

🔊

Audio

Session sound played on the client.

📁

Drive redirection

Folders shared by the client appear in your Linux session as ordinary read-write folders (FUSE).

🖨️

Printer redirection

Client printers show up as CUPS queues, with raw or XPS jobs depending on the printer driver.

⌨️

Input

Keyboard, mouse and cursor shapes.

Install

Packages for x86_64 and aarch64 are attached to every GitHub release.

FormatTargets
.debDebian 13
.rpmFedora, Rocky Linux / RHEL 9 and 10
.tar.gzany of the above (./install.sh)

Run-time dependencies: fuse3, libopenh264, libkscreen. Recommended for printers: cups, ghostscript.

  1. Install the package for your distribution from the latest release.
  2. Start the services 
    systemctl enable --now rdsktp-authd rdsktp
  3. Connect an RDP client to port 3389 with a Linux account and its password.

Configuration lives in /etc/rdsktp/rdsktp.conf, fully commented, with drop-ins in rdsktp.conf.d/. Every setting is explained in the documentation.

Known limits, honestly

RustyDesktop is young. Here is what does not work, or is not verified, today.
  • No NLA in login mode. Authentication is TLS only (dynamic accounts, an IronRDP limit). Use it on a network you trust or behind a VPN.
  • KWin 6.3 (Debian 13): the number of monitors is fixed when a user's session starts, and resizing is done by scaling, with black bars. A newer KWin gives a real resize.
  • Printers: no full Easy Print (MS-RDPEXPS). Tray, duplex and colour choices are not transferred. Validated with software drivers, not yet with physical printers.
  • Clipboard: no primary selection, and not tested with Klipper.
  • SELinux enforcing (Fedora, Rocky) is untested and no policy is shipped.
  • Not covered: smart cards, microphone, USB redirection, several simultaneous clients per user, HiDPI.

Every limit and the reasoning behind each design choice is tracked in the repository's architecture decision records.

Built to be tested

Hexagonal architecture: the domain has no I/O, so it is tested without a compositor or a network.

~80 % line coverage

Measured with cargo-llvm-cov, with a stricter target on parsers, protocols and business logic.

Real-client scenarios

End-to-end tests drive Windows mstsc, FreeRDP and Remmina against a Debian VM, in login mode as well.

Documented decisions

Sixteen ADRs explain the protocol choices, the patches to IronRDP and what was measured. Browse the API reference.
